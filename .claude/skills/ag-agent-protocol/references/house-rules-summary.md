# House writing rules, agent summary

The full rules live in `house-writing-rules.md` and the canonical strings registry in the project docs. Read those before writing anything longer than a label. This summary exists so that alt text, button labels, error states, and one-line UI copy don't trip the rules when a brief leaves them to you.

## Never

- Em dashes. Use a period, a comma, or restructure. One per page is the absolute ceiling; zero is the target.
- Three-item lists ("fast, easy, and clean"). Use two items, or four, or one.
- Trust-pleading adjectives: honest, real, genuine, authentic, transparent, straight, no-nonsense, and their relatives. The copy demonstrates trust; it never claims it.
- Fairness announcements ("we'll be upfront", "in the interest of full disclosure").
- Negative parallelism as rhetoric ("not just X, but Y", "no gimmicks, no tricks, just Z").
- Rhetorical questions with the answer already in the question ("Frizz that won't quit?").
- "Zip" as a standalone noun. "Enter your zip code" is fine as an input instruction; everywhere else say "your water" or "your area."
- Title Case headings. Headings are sentence case.

## Always

- Product name on first reference: "AG Water Softener". Subsequent references: "the AG" or "the softener" are acceptable. Never "the AG" as the first reference in an independently rendered surface (an ad description, a schema description, a standalone block).
- Category descriptor where the product is defined: "shower-arm water softener for renters".
- Mechanism descriptor where the mechanism is named: "ion-exchange shower water softener".
- "Plain non-iodized salt" for the recharge medium. Never "table salt" in site copy.
- Claims match live pages. If a brief asks for a claim you cannot find on the site (a warranty, "no tools", a delivery window), ask before writing it.
- Necessity: the shortest version that carries the fact wins.

## When unsure

Ask. A locked string from the owner costs one message. A guessed string that fails audit costs a redeploy.
